# Wave A Developer Handbook
## AI-Powered CSPM Platform
### Phase 4 (Live Cloud Integration) + Phase 5 (ML Risk Scoring)

> This handbook consolidates the project planning, execution guide and Wave A execution plan into a single implementation guide.

---

# 1. Goal

Wave A delivers two major capabilities in parallel:

1. Live Cloud Scanning (Phase 4)
2. AI/ML Risk Intelligence (Phase 5)

At the end of Wave A the product should:

- Scan a LocalStack AWS account
- Detect cloud misconfigurations
- Store findings in the database
- Run ML models
- Produce Risk Score (0-100)
- Produce Anomaly Flag
- Display all results on the dashboard

# 3. Member Responsibilities

## M1 — Cloud Connector

### Goal
Collect cloud resources from LocalStack and normalize them into the same format as uploaded configuration files.

### Main Deliverables

- boto3 collector
- LocalStack connection
- Resource normalizer
- Unit tests
- Documentation

### Files

backend/cloud/
- collector.py
- normalizer.py
- localstack_client.py
- __init__.py

backend/tests/
- test_collector.py

### Responsibilities

- Connect to LocalStack
- Read S3 buckets
- Read IAM
- Read Security Groups
- Never modify cloud resources
- Convert resources into the common schema

### Output

collect_cloud_resources()

returns

```json
[
 {
  "resource_id":"",
  "resource_type":"",
  "configuration":{},
  "metadata":{}
 }
]
```

### Handoff

Output goes directly to M2.

---

## M2 — Live Scan API + UI

### Goal

Turn M1's collector into a complete scanning feature.

### Backend Files

backend/api/
- live_scan.py

backend/services/
- scan_service.py

### Frontend Files

frontend/pages/
- ScanCloud.tsx

frontend/components/
- ScanButton.tsx

### Responsibilities

- Create POST /scans/cloud
- Call collector
- Run rule engine
- Save scan
- Save findings
- Display scans in dashboard

### Input

Normalized resources from M1.

### Output

Database scan + findings.

### Handoff

Stored findings become input for M4.

---

## M3 — ML Models

### Goal

Build and train the machine learning models.

### Files

ml/

- simulate_resources.py
- mutate_iac.py
- feature_engineering.py
- train_xgboost.py
- train_isolation_forest.py
- benchmark.ipynb
- model.joblib

> **Constraint (evaluator requirement):** no external dataset or third-party IaC module source — the full fleet (normal + anomalous) must be generated by our own code. See `Major Project Planning.md` §8.3.

### Responsibilities

- Generate dataset (fully simulated — no external source)
- Mutate simulated resources to create labeled anomalies
- Create feature matrix
- Train XGBoost
- Train Isolation Forest
- Save models
- Produce benchmark report

### Output

score_findings(findings)

returns

```json
{
 "risk_score":87,
 "is_anomaly":true
}
```

### Handoff

Provide

- model.joblib
- scorer.py
- benchmark report

to M4.

---

## M4 — Product Integration

### Goal

### Files

backend/ml/

frontend/components/

### Input

ML models from M3

### Output

Fully updated dashboard.
